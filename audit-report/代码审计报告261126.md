### 一、P0：实盘阻断级问题（必须修复后再开实盘）

#### N-T1. `ccxt 4.5.x` 币安合约条件单已迁移至 Algo API，止损撤单与查单因缺少 `{"trigger": True}` 100% 失败
- **位置**：[executor.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/executor.py#L158-L166)、[executor.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/executor.py#L180-L200)、[executor.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/executor.py#L242-L248)、[executor.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/executor.py#L430)、[executor.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/executor.py#L463)
- **根因验证**（已核对 `.venv` 内 `ccxt 4.5.93` `binance.py` 源码）：
  1. 下止损单时 `_place_sl_order` 调用 `create_order(symbol, "stop_market", ..., {"stopPrice": sl_price, "reduceOnly": True})`。由于含 `stopPrice`，`ccxt` 判定 `isAlgoOrder = True`，走币安新接口 `fapiPrivatePostAlgoOrder`（`/fapi/v1/algoOrder`），返回的 `id` 是 **`algoId`**。
  2. 但在 `update_stop_loss`（移动止损撤旧单）、`close_position`（平仓后清理止损单）中调用 `self.exchange.cancel_order(sl_order_id, symbol)` 时**未传 `params={"trigger": True}`**；在 `fetch_order_fill` 查询止损单成交均价时调用 `self.exchange.fetch_order(order_id, symbol)` **也未传 `params={"trigger": True}`**。
  3. `ccxt` 在未收到 `stop/trigger/conditional=True` 时，会将请求发往普通订单接口 `fapiPrivateDeleteOrder` / `fapiPrivateGetOrder`（`/fapi/v1/order`），币安必报 `-2011 Unknown order sent` / `-2013 Order does not exist`。
- **实盘后果**：
  - **每次移动止损都会残留旧止损单**（`executor.py:246` 捕获异常仅打 warning），仓位平掉后残余条件单也撤不掉；且同一币种堆积的条件单达到币安上限（`-4045 Reach max stop order limit`）后，**后续新开仓挂止损会直接失败并触发紧急市价平仓**。
  - **交易所触发止损后无法查回真实成交价**，`fetch_order_fill` 恒返回 `None`，只能退回用 ticker 价或预设止损价记账，且 `close_reason` 恒变成 `"exchange_closed"` 而非 `"stop_loss"` / `"trailing_stop"`。
- **修复建议**：所有针对 `sl_order_id` 的 `cancel_order` 和 `fetch_order` 均传入 `{"trigger": True}`（若兼容旧版挂单可在捕获异常后再不带参数兜底一次）；并在平仓清理时可补充按交易对撤销全部未成交条件单的兜底。

#### N-T2. 固定目标止盈 `take_profit`（盈亏比 `rr_ratio`）在实盘、模拟盘、回测中全部未生效
- **位置**：[trader.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/trader.py#L816-L896)、[backtester.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/backtester.py#L277-L312)、[executor.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/executor.py#L298-L327)

#### N-T3. 交易对校验允许 `BTC/USDT` 斜杠格式，在 `ccxt` `defaultType="future"` 下会被解析为现货市场
- **位置**：[models.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/models.py#L15-L22)、[trading.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/routers/trading.py#L131)
- **实测验证**：在当前环境执行 `ex = ccxt.binance({"options": {"defaultType": "future"}})` 后：
  - `ex.market("BTCUSDT")` → 解析为永续合约 `BTC/USDT:USDT`（`linear=True, swap=True`）；
  - `ex.market("BTC/USDT")` → **解析为现货市场 `BTC/USDT`（`spot=True, linear=False`）**！（因为 `ccxt` 中永续统一符号带 `:USDT`，不带 `:USDT` 的 `BTC/USDT` 命中 `self.markets["BTC/USDT"]` 现货字典，仅 `defaultType="swap"` 时才会自动重写为 `:USDT`）。
- **后果**：`validate_symbol_str` 的正则 `^[A-Z0-9]{2,20}(/[A-Z0-9]{2,10})?$` 明确放行了 `BTC/USDT`。一旦用户添加交易对时输入了斜杠，`DataFeed` 拉取 K 线、精度格式化及 `Executor` 下单都会落到现货市场或因 `reduceOnly` 报错。
- **修复建议**：在 `validate_symbol_str` 中统一将输入标准化为无斜杠大写 ID（如 `s.replace("/", "").replace(":USDT", "")`）并只允许 `^[A-Z0-9]{4,20}$`。同时校验 `htf_timeframe` 对应的周期毫秒数必须严格大于 `timeframe`。

#### N-T4. 实盘止损重挂未回写新单号 + 部分平仓未对账数量
- **位置**：[executor.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/executor.py#L444-L450)、[trader.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/trader.py#L754-L757)
- **说明**：
  1. `close_position` 在撤除原止损后平仓失败、触发重挂保护止损（`L446`）时，新生成的止损单 `id` 被直接丢弃并向上抛异常，导致内存 `pos["sl_order_id"]` 与 DB 里存的仍是**已撤销的旧单号**。
  2. `_reconcile_live_position` 只在 `ex_pos["size"] == 0` 时对账平仓；若用户在币安 App 手动减仓一半或发生 ADL 自动减仓（`0 < ex_pos["size"] < pos["quantity"]`），本地 `pos["quantity"]` 不更新，后续移动止损和软件平仓仍按原数量计算盈亏。

#### N-T5. 实盘手续费统计链路存在 3 处断点，实际记账手续费恒为 0
- **位置**：[executor.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/executor.py#L35-L56)、[database.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/database.py#L88-L117)、[trading.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/routers/trading.py#L563-L595)
- **说明**：
  1. 币安 USD-M 合约 `POST /fapi/v1/order`（`newOrderRespType="RESULT"`）返回体中不包含 `commission`/`fee` 字段（仅现货 `FULL` 模式或合约 `fetch_my_trades` 才有手续费），因此 `_extract_usdt_fee(order)` 在实盘实际上总是返回 `0.0`；
  2. `trades` 表没有 `fee` / `entry_fee` 字段，服务重启恢复持仓后开仓手续费即丢失；
  3. 手动平仓接口 `manual_close_trade`（`trading.py:583-595`）完全忽略了 `close_res.get("fee")` 和 `close_res.get("close_reason")`，直接用毛利覆盖写入 DB。

#### N-B1. 回测与实盘的 4 处细节偏差（含同根 K 线激活偏差与期末持仓漏计）
- **位置**：[backtester.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/backtester.py#L277-L364)
- **说明**：
  1. **同根 K 线激活后的乐观偏差**：`backtester.py:282-295` 使用了 `if ... elif not trailing_active ... else`。当某根 K 线最高价触及 `0.88R` 激活保本锁利时，该根 K 线既不会检查收盘是否跌破 `MA25`，也不会检查同根 K 线冲高回落是否打穿刚上移的保本止损；而实盘 `trader.py:831-895` 激活后会立即在同一轮执行 `MA25` 收紧与跌破判断。
  2. **期末未平仓交易完全不计入回测结果**：回测循环结束时若仍有 `in_trade == True` 的持仓，既未按期末收盘价强制结算，也未把浮盈亏和已付开仓手续费计入 `capital` / `equity_history` / `total_pnl`（若最后一笔正处于大幅浮亏，回测报告会显得完全无损）。
  3. **开仓后确认计数重置不一致**：回测开仓时调用了 `strategy.reset()`（`backtester.py:360`），实盘开仓（`trader.py:443`）未调用 `strategy.reset()`。对于秒平/同方向快速再入场场景两者确认次数会相差 1~N 根。
  4. **持仓期间夏普按已实现资金算**：`equity_history`（`L362`）记录的是不含浮盈亏的 `capital`，跨天持仓期间日收益波动为 0，会轻微高估夏普比率。

#### N-B2. 双模式（Paper + Live）同时运行时的状态覆盖竞态与重复日志风暴
- **位置**：[trader.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/trader.py#L133)、[trader.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/trader.py#L260)、[trader.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/trader.py#L1077-L1130)、[app.js](file:///Users/tony/Documents/playground/freedom/ma-trader/frontend/js/app.js#L900-L906)
- **说明**：
  1. **前端运行状态误显示**：`TradingBot.start()` / `stop()` 内部广播 `{"type": "bot_status", "running": True/False}`（**不含** `paper_running`/`live_running` 字段），且经由 `asyncio.create_task` 异步投递；当它晚于 `trading.py` 的 `_bot_status_payload` 到达前端时，`app.js:901-903` 会把 `liveRunning` 重置为 `false`，导致实盘明明在跑，前端按钮却变回“未运行”。
  2. **双倍行情请求与双倍系统日志入库**：模拟与实盘同时开启时，两个 `TradingBot` 各自启动一套完全相同的 `_monitor_symbol` 循环，对同一批币种拉取双倍 REST K 线，且每根 K 线两边都会向 `system_logs` 表写入一模一样的 `[信号] BTCUSDT ...` 记录，WebSocket 前端也会收到双份信号推送。
  3. **自动平仓与手动平仓缺乏原子互斥**：`trader.py:981` 与 `trading.py:580` 之间无锁，极端同时触发时会向交易所连发两次平仓请求；DB 更新建议改为 `UPDATE trades SET ... WHERE id=:id AND status='open'` 并校验影响行数。

#### N-B3. `BinanceWSStreamer` 不支持代理，有代理环境下后台无限重连
- **位置**：[binance_ws.py](file:///Users/tony/Documents/playground/freedom/ma-trader/backend/binance_ws.py#L123-L128)
- **说明**：`DataFeed`、`TelegramNotifier`、`backtest_cache` 均支持读取全局 `http_proxy`，唯独 `BinanceWSStreamer` 的 `websockets.connect(url)` 完全没有接入代理配置。在国内服务器需挂代理访问币安的场景下，WS 流会每隔数秒报错断线重连并轮询全部备用地址。

#### N-B4. 前端 K 线图与实时价格直连币安**现货** WebSocket，且停止实盘不弹持仓警告
- **位置**：[app.js](file:///Users/tony/Documents/playground/freedom/ma-trader/frontend/js/app.js#L1524)、[app.js](file:///Users/tony/Documents/playground/freedom/ma-trader/frontend/js/app.js#L764-L769)
- **说明**：
  1. `connectBinanceStream` 硬编码连接现货流 `wss://stream.binance.com:9443/ws/${streamName}`，并用现货 K 线价格调用 `updateCurrentPrice`（甚至作为 `closeTrade` 默认提交给后端的 `payload.exit_price`！见 `app.js:824`——意味着**前端点击手动平仓实盘/模拟单时，会把现货价格作为 `exit_price` 传给后端**，模拟盘直接按现货价成交！）。应改为 `wss://fstream.binance.com/ws/...` 合约流，且手动平仓默认不传前端缓存价、交由后端统一获取合约实时价。
  2. `stopBot()` 调用 `/api/trading/stop` 成功后未解析返回 JSON 中的 `warning` 字段，用户停止实盘时看不到“交易所仍有 N 笔实盘持仓未平仓”的弹窗提示。

## 第三部分：建议优先修复清单

1. **立即修复（P0 实盘安全）**：
   - **N-T1**：`executor.py` 中对 `sl_order_id` 的 `cancel_order` 与 `fetch_order` 全部补齐 `{"trigger": True}`，并编写针对 `ccxt.binance` 条件单路由的单测；

2. **近期修复（P1 准确性与体验）**：
   - **N-B4**：前端 K 线流切为合约 `fstream.binance.com`，`closeTrade()` 移除默认传前端现货 `exit_price`，`stopBot()` 弹窗展示后端返回的实盘未平仓 `warning`；
